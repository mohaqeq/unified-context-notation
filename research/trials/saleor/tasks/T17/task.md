# Delete a menu item without losing its children

Removing a menu entry from the storefront navigation currently wipes out everything underneath it: `menuItemDelete` deletes the item together with all of its descendants, so a merchant who only wants to drop a grouping entry ("Shop") has to re-create every sub-entry afterwards. Please add an optional `keepChildren: Boolean` argument to `menuItemDelete`. When it is `true`, the direct children of the deleted item, each with its own subtree, are attached to the deleted item's parent instead (or become top-level items of the same menu when the deleted item was top-level), and then the item itself is deleted. When it is `false` or omitted nothing changes: the whole subtree is deleted as today. The mutation still returns the deleted item and triggers `MENU_ITEM_DELETED` only for it.
