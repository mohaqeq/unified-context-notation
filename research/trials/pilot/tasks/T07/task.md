Rule authors keep re-implementing the same "find the neighbouring code segment" loop over `context.siblings_pre` and `context.siblings_post`. Please add two read-only properties to `RuleContext` (in `sqlfluff.core.rules.context`): `previous_code_sibling` and `next_code_sibling`. Each returns the nearest sibling of `context.segment` before/after it (within the same parent) for which `is_code` is true, skipping whitespace, newlines, comments and meta segments, or `None` if there isn't one (including when the context has no parent).
